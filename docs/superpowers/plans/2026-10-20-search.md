# Search — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Basic text search (spec §6): a Search view reachable from the sidebar or with `/` / Ctrl+K, live results as you type.

**Architecture:** `core::search::{words, matches, rank}`: every query word (lower-cased, a leading `@` ignored) must appear in the title, description or labels, in any order. The `search:` filter term uses the same matcher. `AppService::search_at(query, today) -> SearchResults { open, completed }`: open tasks ranked title-matches first, then due date (undated last), then priority; up to 50 completed matches, newest first. The UI's `SearchPane` loads its own results (so typing doesn't re-run the app-wide loader) and keeps the query across visits.

## Global Constraints
- An empty or whitespace query shows a hint and matches nothing.
- Completed matches appear only with "Show completed" on; otherwise the empty state says how many there are.
- `/` opens Search only when not typing in a field; Ctrl/Cmd+K works anywhere. Escape in the box clears it.
