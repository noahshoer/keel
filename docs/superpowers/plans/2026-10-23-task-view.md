# Task View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tapping a task opens a task view (a sheet on the phone, a right-hand panel on desktop) that shows its fields and its direct sub-tasks. Lists become cards that hide sub-tasks, except when a sub-task matches a dated view; then it shows inside its parent's card.

**Architecture:**
- **Core (`keel-core`) holds the pure rules:**
  - sub-task progress counts
  - grouping a view's matches into cards
  - the repeat reset, as a new `Action`
- **The service exposes one new list:** all non-deleted tasks.
- **The Dioxus UI computes cards, counts and the view's contents** from that list with the core functions, so the list, the header and the rows can't disagree. The task view itself is a Dioxus component, shared by every platform.
- **On iOS, only the pickers are native.** A new "picker only" mode on the glass card opens a single picker sheet without the card, and the ••• menu uses the existing native action menu.

**Tech Stack:** Rust, Tauri v2, Dioxus 0.6 (wasm), rusqlite, SwiftUI glass plugin (iOS 26).

**Spec:** `docs/superpowers/specs/2026-10-23-task-view-design.md`

## Global Constraints

- Every feature ships on every platform; the iPhone only differs in display tweaks and Liquid Glass.
- New `Action` variants only; never change an existing serialized shape. New fields are `#[serde(default)]`.
- Tauri commands use `#[tauri::command(rename_all = "snake_case")]`. A command that touches a mobile plugin must be `async`.
- Missing fields are dotted-outline pills ("+ Deadline"), in one row that scrolls sideways on the phone and wraps on desktop.
- Count text: the list and sub-task rows show "x/y"; the view header shows "x of y · Show completed" (or "Hide completed"). When all are done, the count stays and a round green check follows it: "5/5 ✓", "5 of 5 · Show completed ✓".
- Branch `feat/task-view` (already created, with the spec committed). TDD, a commit per task, then merge `--no-ff` to `main` and push. Commit as the noreply address.
- After UI changes: `cd crates/ui && dx build --platform web && cp -r target/dx/keel-ui/debug/web/public/* dist/`.

## Plan decisions (not in the spec)

- **Card grouping uses the top-level ancestor.** A matching grandchild (e.g. *Toothbrush* under *Toiletries* under *Pack for Boston*) shows in *Pack for Boston*'s card. One card per top-level task keeps cards flat. Rows inside a card aren't indented.
- **Orphans:** a task whose parent is missing or deleted is treated as top-level, the same as `views::nest` today.
- **Reopening a sub-task of a completed parent leaves the parent completed.** `TaskUncomplete` is unchanged.
- **A task completed elsewhere stays open in the view**, showing as completed, so it can be reopened. Only completing it from the view's own circle closes the view. A view whose task was deleted is removed from the stack.
- **Repeat reset:** a new `Action::SubtasksReset { id }`, sent right after `TaskComplete` for a repeating task. It's never sent for a one-off task. A re-tap on an already-credited occurrence still resets the sub-tasks. That's harmless, because the occurrence is already done.
- **Location:** an Inbox task with no section shows "+ Location" as a pill. Any other task shows a Location row.
- **Desktop panel:** 360px wide when the window is at least 900px wide. Below that, the phone sheet is used.

## Review Focus

1. **A very long title** in a card header or a view title wraps and never pushes the count or › off the screen. Pinned in Task 9 (the overlap check runs with a 120-character title).
2. **Tapping a sub-task, Back or Done while a title or description edit is unsaved** saves the edit first. Pinned in Task 7 (`pending_save_before_nav`).
3. **A task with 40 sub-tasks** scrolls inside the sheet; the sheet doesn't grow past the screen. Pinned in Task 9 (scroll check).
4. **The view stays correct after any reload:** a sub-task completed from the list underneath, or a parent completed in another view, updates the open view's counts. Pinned in Task 6 (`detail_reflects_reloaded_tasks`).
5. **A sub-task in a different project from its parent** (possible after a move) still groups under its parent and counts toward it. Pinned in Task 2 (`cards_group_across_projects`).
