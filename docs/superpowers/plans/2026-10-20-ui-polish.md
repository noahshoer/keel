# UI Polish — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** The user's list — (1) responsive layout, (2) fix the calendar UI, (3) fix the drop-down UI, (4) highlight the processed natural language — so the editor feels like Todoist's rather than a form of native browser controls.

**Architecture:** Native `<input type=date|time>` and `<select>` chips are replaced by custom popovers sharing one popover/backdrop pattern (one open at a time per editor; a transparent full-screen backdrop closes it). The date popover is Todoist's scheduler: quick picks, a month grid built by a pure `core::calendar::month_weeks`, and a time field parsed with the quick-add time grammar. Quick add reports the byte spans it recognized (`QuickAdd.spans`), and the title becomes an auto-growing textarea over a mirror that paints those spans.

**Branch:** `feat/ui-narrow-layout` (Task 1 already committed there).

## Global Constraints
- No native date/time/select controls remain in the task editor.
- Popovers stay on screen at 375px wide (anchored full-width under the chips on narrow layouts).
- Highlighting only in add mode (quick add); the edit title is plain.
- Enter in the title submits; Shift+Enter is ignored (titles are single-line); Escape closes an open popover, else cancels.

## Review Focus
- **Span byte offsets** with multi-byte characters and repeated whitespace — Task 4.
- **Month grid** starts Monday, always 6 weeks, crosses year boundaries — Task 2.
- **Mirror alignment**: textarea and mirror share font, padding, wrapping — Task 4.

## Notes
