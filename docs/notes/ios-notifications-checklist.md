# iOS notifications — Mac checklist

Everything except building and running on iOS was done on Windows. This is the one sitting on the Mac.

## 1. One-time setup (about 20 minutes)
1. Install **Xcode** from the App Store, open it once, and accept the license. Then install the command-line tools:
   ```bash
   xcode-select --install
   ```
   Xcode doesn't always include an iOS Simulator runtime (`xcrun simctl list runtimes` is empty). Download one (several GB):
   ```bash
   xcodebuild -downloadPlatform iOS
   ```
   Install CocoaPods with Homebrew. Tauri falls back to `gem install`, which needs sudo:
   ```bash
   brew install cocoapods
   ```
2. Install the Rust iOS targets:
   ```bash
   rustup target add aarch64-apple-ios aarch64-apple-ios-sim
   ```
3. Install the Tauri CLI (same as on Windows):
   ```bash
   cargo install tauri-cli --version "^2"
   ```
4. Clone the repo and set up the web UI (Node 24, `corepack enable` once, `cd web && pnpm install`, and from the repo root `cargo install wasm-bindgen-cli --version 0.2.129 --locked --root .tools`). Tauri builds it itself (`beforeDevCommand` / `beforeBuildCommand`).
5. The Xcode project (`crates/src-tauri/gen/apple`) is committed, generated by `cargo tauri ios init` on 2026-10-20. Don't re-init. After changing `icons/keel.svg`, run `cargo tauri icon icons/keel.svg` **on the Mac**: the iOS icon set is only written when `gen/apple` exists.

## 2. Run it
- **Simulator:**
  ```bash
  cd crates/src-tauri && cargo tauri ios dev
  ```
  Pick an iPhone simulator when asked.
- **Your iPhone:** plug it in, enable Developer Mode (Settings → Privacy & Security), then run the same command and pick the phone. Xcode needs a signing team: open `gen/apple/*.xcodeproj` → target → Signing & Capabilities → pick your Apple ID team. (A free Apple ID works; the install expires after 7 days.)

## 3. What to check
- [x] Settings (gear) → turn on **Task reminders** → iOS shows the "Allow notifications?" prompt → Allow → the switch stays on.
- [x] **Send test notification** → a banner appears (pull down Notification Center if the app is in front).
- [x] Add a task due 2 minutes from now (pick today and a time two minutes ahead in the date picker), then **close the app** (swipe it away). The reminder arrives on time.
- [x] Complete a task that had a pending reminder → it no longer fires.
- [x] Turn on **Daily summary**; the "Coming up" list shows it.
- [x] Tapping a notification opens the app.
- [x] If you deny permission: the switch stays off and the panel says notifications are blocked.

Simulator results (iPhone 16, iOS 18.6, 2026-10-20): all checks above pass. To re-test the deny case, uninstall the app (`xcrun simctl uninstall booted com.nshoe.keel`; this deletes its data) so iOS asks again.

## Debugging notes
- Rust `eprintln!` output appears in the simulator's system log: `xcrun simctl spawn booted log show --last 5m --style compact --predicate 'process == "Keel"' | grep reminders:`.
- iOS's pending notifications live in `~/Library/Developer/CoreSimulator/Devices/<udid>/data/Library/UserNotifications/*/PendingNotifications.plist` (an NSKeyedArchiver plist; read it with Python's `plistlib`).
- `tauri-plugin-notification` 2.7 on iOS: `Schedule::At` reads the time as device-local (upstream #3256; we send the local time labeled UTC), and `pending()` / `cancel_all()` always fail (we track the scheduled ids ourselves). See `upstream-notification-ios-issue.md`.

## Known limits (v1)
- Reminders are planned for the next 14 days, at most 60 at a time (iOS keeps 64). They re-plan every time you open the app or change a task, so far-off tasks get scheduled as they come into range.
- Tasks added on another device only get reminders on this phone after sync is turned on.
